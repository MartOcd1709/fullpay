 FullPay · HackCache '26 · Low-Level Design · Rev B (post 3-lens review, ~45 findings folded in) 
 FullPay LLD 
 Build from this. Schema DDL, module contracts, algorithms, API table, state machine, seed, tests, env. Binds to the HLD and plan Rev D. 
 Global invariants: plain JavaScript · money = Number integer paise end-to-end, BigInt nowhere (pg parsers set to Number; asPaise() throws on unsafe ints) · rates = integer basis points · quantities = qty_milli INT · dates = YYYY-MM-DD IST strings via lib/time.js only · every write that changes invoice state happens in one transaction with its chain event · errors = {error:{code,message}} with 400 validation · 401 auth · 404 unknown · 409 locked · 410 expired.

 CREATE TABLE customers (
 id BIGSERIAL PRIMARY KEY, name TEXT NOT NULL, address TEXT NOT NULL,
 gstin TEXT, state_code TEXT NOT NULL, -- gstin NULL = unregistered; check digit validated in app
 credit_days INT, -- NULL = nothing agreed in writing ⇒ statutory 15 days

 preferred_channel TEXT NOT NULL DEFAULT 'email' CHECK (preferred_channel IN ('email','wa','sms')),
 opt_out BOOLEAN NOT NULL DEFAULT FALSE, created_at TIMESTAMPTZ NOT NULL DEFAULT now());
CREATE TABLE invoices (
 id BIGSERIAL PRIMARY KEY,
 fy TEXT NOT NULL, seq INT, -- seq allocated at /send (drafts have none)
 number TEXT, -- 'INV/26-27/0007' (≤16 chars), set with seq
 customer_id BIGINT NOT NULL REFERENCES customers(id),
 issue_date DATE NOT NULL, acceptance_date DATE, -- NULL ⇒ issue_date

 rung TEXT CHECK (rung IN ('heads_up','due_date','overdue_gentle','overdue_firm','demand_letter','odr_guidance')),

 5 · Interest engine (interest.js) — the correctness wedge 
 computeInterest({ invoice, allocations, acceptedSpans, cfg, asOf })
 → { segments:[{from,to,days,rate_bps,principal_paise,interest_paise}], total_paise, principal_now_paise, conventions }
 1 creditDays = invoice.credit_days ?? 15 // NULL = nothing agreed in writing ⇒ statutory 15, interest from day 16
 due = (invoice.acceptance_date ?? issue_date) + creditDays ; start = dayAfter(due)
 2 asOf < start → zero result. Startup check: RBI series must cover start, else throw.
 3 boundaries = sorted unique of: start, asOf, RBI 'from' dates in (start,asOf], monthly rests
 (addMonths(due,n) for n≥1), allocation value_dates, acceptedSpan edges.
 4 base = total_paise − Σ allocations.value_date ≤ start (clamped ≥ 0); accrued = 0
 5 for each [a,b) between boundaries:
 inSpan = a inside an accepted dispute span // span = [dispute_opened.ts, dispute_accepted.ts)
 rateBps = inSpan ? 0 : seriesRateAt(a) × cfg.interest.multiplier // rests still fire inside spans
 seg.interest = Math.round(base × rateBps × days(a,b) / (10000 × cfg.interest.day_count)) // integer paise, half-up
 accrued += seg.interest
 at b: if b is a monthly rest → base += accrued; accrued = 0 // compound (monthly rests)
 if b is an allocation → (rest first on a shared date, then allocate)
 interest_first: pay = min(alloc, accrued); accrued −= pay; base = max(0, base − (alloc − pay))
 principal_first: base = max(0, base − alloc)
 6 final partial period: simple accrual, no compounding at asOf
 7 total_paise = Σ seg.interest // letter table sums by construction
Conventions footnote printed on the letter; rejected disputes exclude nothing. 
 ⚠ Pre-event: real RBI series; appropriation order from the Act/MSEFC practice → set cfg.interest.appropriation , un-skip that branch's golden test.

 7 · State machine (ladder.js) 
 Global preconditions for every advance: status ∈ {sent, part_paid} · paused_by IS NULL · snoozed_until IS NULL OR today > snoozed_until · !customer.opt_out · customer under messaging.max_per_customer_per_day for this rung/channel. Entry & unpause rule: target = highest rung whose due + offset ≤ today ; intermediate rungs are skipped with rung_skipped events only (no messages); exactly one message (the target rung's) is queued; max one advance per invoice per tick . Tick = one transaction on one client, pg_try_advisory_xact_lock(7) else 409, serial loop grouped by customer (demo-scale ceiling, by design).
